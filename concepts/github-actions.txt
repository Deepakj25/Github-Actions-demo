GitHub Actions

Definition

Built-in GitHub automation platform.
Executes workflows in response to events.
Primarily used for CI/CD.

Execution Flow

Event
   ↓
Workflow
   ↓
Job
   ↓
Runner
   ↓
Steps
   ↓
Runner Deleted


Key Points

Workflow starts when an event occurs.
Jobs execute on runners (VMs).
GitHub-hosted runners are ephemeral.
After the job completes, the runner is deleted.

Source code
Branches
Pull Requests
Code Reviews

Key Takeaway
GitHub Actions brings CI/CD and automation directly into GitHub, eliminating the need for a separate CI/CD platform in many 
scenarios while keeping workflows version-controlled alongside the application code.

Repository contains one or more workflows.
Workflow contains one or more jobs.
Job runs on a single runner.
Runner executes the job.
Job contains one or more steps.
Step executes either a shell command (run) or a reusable action (uses).

Workflow File Location

Workflows must be stored in:
.github/workflows/
GitHub automatically discovers workflows from this directory.
Workflow files use .yml or .yaml.
A repository can contain multiple workflow files.
Workflow files outside .github/workflows/ are ignored.
