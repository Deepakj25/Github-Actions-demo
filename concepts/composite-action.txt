// Composite Action -> collection of steps.
-> called at step level

How is this different from Reuable workflow
1. Resuable workflow are called at job level
2. Compsoite actions are called at step level

ex.

we need to create actions folder in repo (.github/actions/<folder-name>/action.yaml). or action.yml
ex. .github/actions/hello/action.yaml

steps:
  - uses: ./.github/actions/hello

//Concept
We add a Action directoty not full path containing action.yaml
Github automatically loads the below supported file if present in the directory

action.yaml
action.yml
Dockerfile.

//Passing inputs
we can pass the paramter same as we pass in workflow
Composite action inputs are treated as strings; unlike reusable workflow inputs, you don't declare type: boolean, type: number, etc.

// env variables in calling workflow can be used inside composite acrtion
since the env variables are part of job
-> it can be used with $var_name

Composite actions can consume inputs.
Composite-action inputs are passed with with:.
Environment variables are accessed through the shell, e.g. $APP_ENV.
GitHub contexts such as github.* and runner.* can be used in composite-action steps.
