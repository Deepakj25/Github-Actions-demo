Artifacts are for files, not variables.

Upload using:
uses: actions/upload-artifact@v4

Download using:
uses: actions/download-artifact@v4

Artifacts are stored by GitHub.
Use them to move build outputs, reports, logs, and binaries between jobs.

If someone asks:
Why use Artifacts instead of rebuilding?

A strong answer is:
Artifacts ensure that the exact binary tested is the binary deployed.
This eliminates inconsistencies caused by rebuilding in later stages or jobs.

Azure DevOps Mapping
| Azure DevOps               | GitHub Actions              |
| -------------------------- | --------------------------- |
| Publish Pipeline Artifact  | `actions/upload-artifact`   |
| Download Pipeline Artifact | `actions/download-artifact` |
| Pipeline Workspace         | GitHub Artifact Storage     |

Case1;
Build produces many files (txt , html , .zip)
1. We can either package everything in one zip
2. we can upload multiple zips -> jobs can download only what they require -> no unnecssary downlaods.

Retention Period (it used default if not specifed)
Post Retetion perioid Artifacts are deleted.

- uses: actions/upload-artifact@v4
  with:
    name: backend
    path: backend.zip
    retention-days: 7
